## 二、P1 级问题（必须修复，阻断后续 Task）

### P1-1 校验器命令行入口在 Windows 上静默失效（Task 3 遗留 bug）

- **现象**：`node tests/validate-corpus.mjs corpus` 退出码 0、无任何输出。
- **原因**：`tests/validate-corpus.mjs` 的命令行入口判断：

  ```javascript
  if (import.meta.url === `file://${process.argv[1]}`)
  ```

  在 Windows 上 `process.argv[1]` 是 `tests/validate-corpus.mjs`（相对路径），与 `import.meta.url`（`file:///D:/MentalTutor/...`）格式不同（缺前导斜杠、反斜杠/正斜杠差异），**该判断永远为 false，主体代码从不执行，静默退出 0**。
- **影响**：Task 4-13 各步的"运行校验 → 确认通过"（Step 3）、Task 14 Step 1/2 全量校验、Task 18 Step 7 全量校验，全部是**假通过**。导出函数逻辑本身正确（直接调用验证 355 条全合法），但命令入口形同虚设。
- **修复方案**（一行，改命令行入口判断）：

  ```javascript
  import { pathToFileURL } from 'node:url';
  // ...其他代码不变...
  if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
    // 原命令行入口主体
  }
  ```

- **验证方式**：修复后 `node tests/validate-corpus.mjs corpus` 必须输出 `✓ N 条语料全部合法`。

### P1-2 禁用场景覆盖率 90% 为空（Task 4-13 质量问题）

- **现象**：355 条中 320 条（90%）`禁用场景` 为空数组。
- **规范冲突**：设计文档 §8.3 引用纪律明确"**每条语料必须标注禁用场景——这是防'开错药'的最后一道闸**"；但校验器允许空数组（宽容），计划 Task 4-13 也未对覆盖率设硬性验收 → 执行 agent 按校验器执行，违背 §8.3。
- **影响**：
  - 角色卡处方依赖"回避/慎用"信息，空禁用场景使防误用机制大面积缺失；
  - **纸版工具包（§8.8）无 AI 把关，"回避是唯一安全阀"——安全阀 90% 缺失**，与 §8.8 物化原则直接冲突；
  - 抽查显示，"知足""放下""安之若命"类**高风险论断条目**（最需要禁用场景的）也多为空。
- **修复建议**：
  1. 校验器增加"禁用场景为空"警告（不阻断，输出 warning 计数）；
  2. 主声部补禁用场景，达标线：**高风险论断条目（知足/放下/不争/安之若命/无为等）必须标注**，整体覆盖率目标 ≥ 60%；
  3. 计划 Task 4-13 验收补充该指标。
