## 二、骨架合理性评估（逐项）

| 目录 | 意图解读 | 评估 |

| `bin/` | 可执行入口（如 `mingtian` 命令） | ✅ 合理，入口与逻辑分离 |

| `lib/prompt/` | 角色卡/提示词组装 | ✅ 合理——角色卡 v0.6 是核心资产，组装逻辑独立正确 |

## 三、关键缺失设计决策（7 项，审视核心）

1. **产品形态未定**（§11 仍在"待决"）：CLI 交互式会话 / 单次 stdin 管道 / 网页 / 微信机器人。骨架已暗示 CLI 方向，但无界面规格：交互循环、多轮记忆、退出方式都未定义。
2. **诊断路由架构未定**（最关键）：设计文档说"诊断路由代码化"——路由逻辑有三种实现：
   - a) 纯 prompt 内矩阵（让 LLM 按角色卡矩阵自行判断）——最简单，但"追问机制"的会话状态难管
   - b) 硬编码矩阵表（CLI 层用代码判断困境类型再注入对应语料）——可控但要把 358 条语料按五类预分
   - c) 混合：prompt 内矩阵 + CLI 层管理"追问状态"——推荐
3. **API key 与配置管理未定**：key 存哪、怎么读、会不会进 git/日志——**安全红线**（见 §四-1）
4. **语料注入策略未定**：358 条不能全注入（token 爆炸）。建议利用语料的"适用场景"字段按困境类型预筛选注入（每类几十条），RAG 留到阶段 4
5. **会话状态管理**：明镜有"追问机制"（信息不足先问、等回答再开方）——CLI 需要"等待用户回答追问"的状态机，否则追问机制在 CLI 里会失效
6. **模型参数与版本锁定**：temperature 等参数、角色卡版本（v0.6）锁定、模型行为差异的兜底（GLM 不用马克思 vs mimo 用——同案例不同模型处方不同，CLI 应记录所用模型）
7. **自动化验收**：阶段 3 验收"五类困境各跑通 3 个案例"应脚本化（复用 eval/trial-set.md + 模型调用），否则无法回归

## 四、风险点

1. **API key 泄露（高危）**：`.gitignore` 目前不保护 `.env`。若 CLI 方案把 key 写进代码或默认文件，一旦提交即泄露。**必须先加保护再开发**：`.env` 进 `.gitignore`、提供 `.env.example`、key 只从环境变量读取。
2. **token 超限**：角色卡（约 8KB）+ 语料全量注入必然超上下文窗口——注入策略是硬约束。
3. **多模型行为漂移**：已实测证实。CLI 需在输出中标注所用模型，且验收要对每个模型单独跑。
4. **危机转介无人工兜底**：CLI 场景下自伤信号转介（边界第 1 条）依赖 LLM 自觉执行，没有人类监督。需在 CLI 帮助信息里明确"本工具不替代专业帮助"。
5. **空目录陷阱**：bin/lib 骨架无代码会诱导"从 RAG 开始写"的错误顺序——应先做最小可跑通（入口+llm+prompt），rag 后置。

---

## 五、建议的最小可行方案（MVP 规格）

```
形态：CLI 交互式会话（一条命令启动，多轮对话，Ctrl+C 退出）
配置：环境变量 MINGTIAN_API_KEY + MINGTIAN_MODEL；.env 进 .gitignore，.env.example 入库
结构：bin/mingtian（入口）→ lib/llm/{client,config}（多模型适配）→ lib/prompt/build（组装 v0.6 角色卡）
诊断路由：prompt 内矩阵 + CLI 状态机（normal / awaiting-answer 两种状态）
语料注入：按五类困境预筛选注入（利用 corpus 的"适用场景"字段），不引 RAG
验收：脚本复用 eval/trial-set.md 跑 5 类 × 3 案例，输出落 eval/phase1-cli-<model>.md
先不做：lib/rag（阶段 4）、网页/机器人（待形态验证后再议）
```

## 六、结论与下一步

- **结论**：目录骨架的方向（入口+模型适配+提示词组装）正确，但 **lib/rag 应撤销或冻结**；在写任何代码前必须先补齐 7 项决策中的 2 项硬约束（API key 安全、语料注入策略）和 1 项架构决策（诊断路由）。
- **建议执行顺序**：① 修 `.gitignore`（加 `.env`）→ ② 撤销/冻结 `lib/rag` 空骨架 → ③ 定 MVP 规格（采纳 §五 或修改）→ ④ 实现 → ⑤ 用 eval 自动化验收。
- **待用户决策**：是否按 §五 MVP 规格实现 CLI（阶段 3 从"可选"转"落地"）；或先保持设计态，CLI 留待之后。
